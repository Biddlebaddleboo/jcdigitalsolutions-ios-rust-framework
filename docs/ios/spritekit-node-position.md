# iOS SpriteKit node position

`ios-spritekit` creates one retained, detached SpriteKit `SKNode` and reads or replaces only its parent-local `position` through the `framework-spritekit::SpriteNodePositionBackend` contract. `SpriteNodePosition` rejects non-finite coordinates, and the adapter also checks that each value is representable by the target's `CGFloat` before a native setter call. `IosSpriteNode::native_node` returns a borrow for host-owned SpriteKit integration; the borrow cannot outlive the Rust wrapper.

Apple's current `SKNode` documentation marks the class `@MainActor`, describes `position` in the parent's coordinate system, and states that `SKNode` itself draws no content. The wrapper requires `ios_runtime::main_thread::MainThread` at construction, checks main-thread context for each read/write, and is explicitly `!Send`/`!Sync`. An off-main read/write returns `ErrorKind::Platform`; a non-finite native value or a position not representable by the target's `CGFloat` returns `ErrorKind::InvalidInput`. The host owns any scene, view, hierarchy placement, and rendering; this crate does not create or present an `SKScene` or `SKView`, attach nodes, load assets, or run a render loop.

The iOS 26.5 public `SpriteKit/SKNode.h` declares `-init`, `position` as `CGPoint`, and `setPosition:` with no per-symbol `API_AVAILABLE` or `API_UNAVAILABLE` macro. Apple's iOS 7.0 API differences list SpriteKit as an added framework, which is the API floor used for this base class and these unannotated members. The active SDK's `SDKSettings.plist` minimum deployment target is iOS 12.0; the device link probe uses 12.0 and the Simulator probe uses the repo's 14.0 Simulator baseline. Those link-probe `minos` values are validation targets, not a raised API floor; this toolchain does not validate deployment below iOS 12.0.

The binding ecosystem has no cached `objc2-sprite-kit` 0.3.2 crate. The iOS adapter therefore uses a minimal local `objc2::extern_class!` declaration for `SKNode : UIResponder` and three typed method declarations that match the public SDK header. The class type is main-thread-only, and the handle contains `PhantomData<Rc<()>>` to prevent send/sync migration and off-thread `Drop`. The crate links SpriteKit explicitly. No permission, usage-description plist key, entitlement, or additional app service setup is required for this detached node operation.

The build/link probe is compile-only and is never run. It checks direct imports of CoreFoundation, Foundation, SpriteKit, UIKit, `libSystem.B.dylib`, and `libobjc.A.dylib`, plus `SKNode`, `position`, and `setPosition:` strings and the link target's minimum OS. It does not verify app execution, rendered output, scene attachment, animation, physics, performance, or SpriteKit parity.

Apple sources: [SKNode](https://developer.apple.com/documentation/spritekit/sknode), [SpriteKit](https://developer.apple.com/documentation/spritekit), and [iOS 6.1 to iOS 7.0 API Differences](https://developer.apple.com/library/archive/releasenotes/General/iOS70APIDiffs/index.html).
