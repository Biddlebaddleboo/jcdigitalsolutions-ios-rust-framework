# iOS VoIP PushKit client

`ios-voip-pushkit` owns an opt-in `PKPushRegistry` configured for `PKPushTypeVoIP`. Create and retain `IosVoipPushService` on the main thread at app launch; PushKit does not deliver to the app until a registry requests the type and has a delegate. `invalidate()` clears requested types and the registry's weak delegate. `Drop` is a cleanup fallback, not a substitute for launch-time ownership.

The API emits exact token bytes on PushKit's token callback and a typed invalidation event. Treat the token as opaque and sensitive; send it only to the app's authenticated APNs provider. Receiving token bytes does not prove provider-server registration, APNs delivery, or VoIP call readiness. PushKit registration has no separate successful-registration result in this API.

Incoming payload dictionaries are copied to UTF-8 JSON bytes; the app owns payload validation and interpretation. On apps linked against the iOS 13 SDK or later, Apple requires VoIP pushes to be reported through CallKit. After parsing a payload, build an `IncomingCall` and call `IncomingVoipPush::report_incoming`; it uses `ios-call-provider::CallProvider::report_incoming` and completes PushKit only after the asynchronous CallKit report callback. Callers with a separate supported CallKit implementation can use `finish_after_callkit_report` only after that implementation's report callback. Dropping the event calls the native PushKit completion exactly once as a leak-safe fallback, but does not meet the CallKit reporting requirement. An unparseable app payload therefore remains an app-level call-policy failure, not a framework claim of successful handling.

The host app must configure the Push Notifications capability/`aps-environment` entitlement and the `UIBackgroundModes` entry `voip`; the app's provider must send VoIP pushes through APNs using the token. This package adds no entitlement, background mode, APNs server, payload protocol, identity, signaling, CallKit provider, or audio handling. Apple limits VoIP push payloads to 5 KB. The package floor is iOS 11.0 because it implements the completion-bearing incoming-push delegate method; device and Simulator compilation/link inspection do not prove APNs registration, delivery, CallKit acceptance, system UI, or on-device lifecycle behavior
