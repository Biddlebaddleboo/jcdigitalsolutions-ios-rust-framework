## Mandatory external contract
- Freeze one stable direct executable name each, proposed `ios-rust-build` and `ios-rust-validate`, installed for the **build host** on `PATH`. Both expose `--help`, `--version`, protocol/schema compatibility and machine-readable diagnostic/error output. No auto-upgrade, implicit latest downloads or unpinned execution.
- Version a declarative build spec and validation spec independently from tool releases; accept specified workspace root and config path, use explicit target triple, deployment floor, source/header paths and feature guards. Reject incompatible schema majors, unsafe paths, unknown flags, malformed IDs, missing toolchain or wrong host.
- Tool binary distributions require immutable source SHA and release ID, SHA-256, recorded compiler version and origin, reproducible provisioning procedure, verified host triple. At minimum support CI Ubuntu x86_64 and macOS arm64; add other host triples only when tested. Artifacts may be packaged in the repo or obtained from immutable pinned release assets, but choose **one canonical, verified install mechanism**, including offline-cache policy. Never let absent tooling cause a silent skip/pass.
- Separate maintenance source from ordinary checkout by a **tracked deletion** of only engine implementation/private engine tests after full parity. Preserve immutable Git provenance or a maintenance-only repository and documented rebuild route. This is context isolation, not a security access control.
