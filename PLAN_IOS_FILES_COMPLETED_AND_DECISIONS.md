## Completed no-go / duplicate-API assessments

- `PLAN_IOS_FILE_EXTENTS.md`: Obsolete/HFS-specific data/resource extent attributes give incomplete and potentially inaccurate physical maps; no facade consumer. Original bounded SDK evidence and rationale at `36e3090a79a2fdbc8f348ccb89fe773c3dbb1247:PLAN_IOS_FILE_EXTENTS.md`.
- `PLAN_IOS_FILE_FORK_LIST.md`: ATTR_FILE_FORKLIST payload format is not publicly defined; no stable typed contract or fork enumeration consumer. Original bounded SDK evidence and rationale at `36e3090a79a2fdbc8f348ccb89fe773c3dbb1247:PLAN_IOS_FILE_FORK_LIST.md`.
- `PLAN_IOS_FILE_OBJECT_PERMANENT_ID.md`: No justified safe persistent identity contract; retain bounded (device,inode) near-time semantics. Original bounded SDK evidence and rationale at `36e3090a79a2fdbc8f348ccb89fe773c3dbb1247:PLAN_IOS_FILE_OBJECT_PERMANENT_ID.md`.
- `PLAN_IOS_VOLUME_UUID.md`: No consumer needs volume UUID; neither persistence nor app-container identity is guaranteed. Original bounded SDK evidence and rationale at `36e3090a79a2fdbc8f348ccb89fe773c3dbb1247:PLAN_IOS_VOLUME_UUID.md`.
- `PLAN_IOS_VOLUME_NAME.md`: Volume name is mutable and unrelated to a safe application-directory operation. Original bounded SDK evidence and rationale at `36e3090a79a2fdbc8f348ccb89fe773c3dbb1247:PLAN_IOS_VOLUME_NAME.md`.
- `PLAN_IOS_VOLUME_CAPABILITIES.md`: Raw capability bitfield insufficient for an app-facing preflight, valid-mask and policy semantics; avoid generic snapshot. Original bounded SDK evidence and rationale at `36e3090a79a2fdbc8f348ccb89fe773c3dbb1247:PLAN_IOS_VOLUME_CAPABILITIES.md`.
- `PLAN_IOS_VOLUME_QUOTA_SIZE.md`: Volume maximum is not a reliable sandbox/app quota. Original bounded SDK evidence and rationale at `36e3090a79a2fdbc8f348ccb89fe773c3dbb1247:PLAN_IOS_VOLUME_QUOTA_SIZE.md`.
- `PLAN_IOS_VOLUME_MOUNT_POINT.md`: Native mount path leaks irrelevant absolute-root detail and does not improve descriptor-relative sandbox access. Original bounded SDK evidence and rationale at `36e3090a79a2fdbc8f348ccb89fe773c3dbb1247:PLAN_IOS_VOLUME_MOUNT_POINT.md`.
- `PLAN_IOS_FILE_CREATION_TIME.md`: Darwin st_birthtime may substitute ctime without an availability bit; never expose as guaranteed creation time. Original bounded SDK evidence and rationale at `36e3090a79a2fdbc8f348ccb89fe773c3dbb1247:PLAN_IOS_FILE_CREATION_TIME.md`.
- `PLAN_IOS_FILE_PROTECTION_CLASS.md`: No public stable mapping from raw F_GETPROTECTIONCLASS value to named Foundation protection class. Original bounded SDK evidence and rationale at `36e3090a79a2fdbc8f348ccb89fe773c3dbb1247:PLAN_IOS_FILE_PROTECTION_CLASS.md`.
- `PLAN_IOS_FILE_FORK_COUNT.md`: Fork count alone cannot enumerate/read forks and is not an actionable app-data capability. Original bounded SDK evidence and rationale at `36e3090a79a2fdbc8f348ccb89fe773c3dbb1247:PLAN_IOS_FILE_FORK_COUNT.md`.

These are completed *research decisions*—not evidence that the underlying Apple API cannot ever be used. Do not reintroduce a rejected property absent a new concrete consumer, verified public contract and revised safety/availability assessment.

## Additional bounded filesystem closures (reviewed at 42f95cbb6bd212dc68231386e86a58b02716cf46)

The six retired planning files below remain available **verbatim** at immutable paths `42f95cbb6bd212dc68231386e86a58b02716cf46:<filename>`. This is retirement of **bounded planning instructions**, not a claim of complete filesystem support or Apple runtime behavior. Source entrypoint: `platform/ios/ios-files/src/lib.rs::IosFiles`; developer contract: `docs/ios/files.md`. The four implemented symbols and their documentation were checked in the snapshot. These records preserve distinct semantics and negative decisions; do not generalize them to the portable `FileBackend` or substitute metadata snapshots for access/identity guarantees.

- **B90 — `PLAN_IOS_FILE_SIZE.md`**: `IosFiles::regular_file_size(AppPath) -> Result<u64, FileError>` reads one `fstatat(AT_SYMLINK_NOFOLLOW)` regular-file `st_size` through validated descriptor-relative paths. Negative size or a nonregular final entry is `InvalidInput`; missing entry is `NotFound`; other errors retain POSIX mapping/code. Read-only synchronous point-in-time metadata, not a content lock, allocation, security-scope grant or portable contract; concurrent directory-rename containment caveat remains. **B265 no-go**: do not introduce equivalent `ATTR_FILE_DATALENGTH` via `fgetattrlist`; B242/B251 are distinct all-fork/resource-fork quantities. Original plan includes iOS 10 floor, SDK/dependency details, exact static commands and privacy rationale. Static iOS device/simulator check/Clippy/rustdoc passed; no tests, linked consumer or runtime filesystem operation.
- **B105 — `PLAN_IOS_FILE_LINK_COUNT.md`**: `IosFiles::regular_file_hard_link_count(AppPath) -> Result<u64, FileError>` widens the no-follow `st_nlink` of a *regular file*; rejects symlinks/directories/special entries, preserves POSIX errors, and cannot enumerate aliases, establish exclusivity or guarantee future identity. **B264 no-go**: do not duplicate with equivalent `ATTR_FILE_LINKCOUNT`, whose `fgetattrlist` path adds filesystem/privacy considerations. Original includes exact source/SDK types and iOS-target static checks. No live operation or consumer execution.
- **B96 — `PLAN_IOS_FILE_MODIFICATION_TIME.md`**: `IosFiles::entry_modification_time(AppPath) -> Result<IosFileModificationTime, FileError>` returns signed Unix seconds plus `u32` nanoseconds from final-entry `fstatat(AT_SYMLINK_NOFOLLOW)`, including the symlink's own metadata. Invalid nanoseconds (outside `0..1_000_000_000`) give `InvalidInput`; missing entry maps `NotFound`. Not a content-version, change token, durability proof, precise filesystem clock or portable API. Original records mapping, concurrent rename limitation, SDK floor and static checks; no runtime test.
- **B152 — `PLAN_IOS_VOLUME_READ_ONLY.md`**: `IosFiles::volume_is_read_only(AppDirectory) -> Result<bool, FileError>` calls `fstatfs` on a retained semantic-directory root and checks `MNT_RDONLY`. Unsupported directory gives `Unsupported`; POSIX errors are preserved. This is a momentary *volume mount* property, not app/path write permission; real writes remain authoritative. Apple lists `fstatfs` under required-reason Disk Space APIs; the host must select and declare its applicable privacy-manifest reason (see B137). The original plan specifies validation commands but **does not record that they passed**; do not infer execution or Xcode 27 qualification.
- **B262 — `PLAN_IOS_FILE_TYPE.md`**: closed **no-go** for `ATTR_FILE_FILETYPE` (`0x00000040`, marked always zero/reserved in reviewed iPhoneOS 26.5 SDK/docs). Use existing `fstatat(AT_SYMLINK_NOFOLLOW)` → `FileKind` classification; reconsider only if Apple changes documented semantics. No API/source/test/runtime behavior added.
- **B161 — `PLAN_IOS_VOLUME_MOUNT_RESTRICTIONS.md`**: closed **no-go** for exposing `MNT_NOEXEC`, `MNT_NOSUID`, `MNT_NODEV`, `MNT_DONTBROWSE`, `MNT_QUOTA` or raw `f_flags` as per-path capability. They describe mount policy, not sandbox execution/writability, browsing rights, app quota or effective authorization. Keep only B152's narrow read-only query; no API/source/test/runtime behavior added.
